# @event-calendar/core v5.12.0 drag/drop findings

## Source-backed answers

1. `eventDrop` does expose the original pointer event as `info.jsEvent`, and `eventDragStop` also receives `jsEvent`. In `Action.svelte`, `eventDragStop` is called with `{ event, jsEvent, view }`, and `eventDrop` is built from `createCallbackInfo(...)` plus `revert()`.
2. There is no built-in Ctrl/Cmd-copy behavior in v5.12.0. The interaction code handles drag/resize/select/click, but there is no branch for modifier keys and no duplicate/copy option in the public API.
3. The component instance exposes these methods: `setOption`, `getOption`, `refetchResources`, `refetchEvents`, `getEvents`, `getEventById`, `addEvent`, `updateEvent`, `removeEventById`, `getView`, `unselect`, `dateFromPoint`, `gotoDate`, `next`, `prev`.
4. `eventDrop` info contains: `event`, `oldEvent`, `oldResource`, `newResource`, `delta`, `revert`, `jsEvent`, `view`.
